# Design Spec: Mobile SQLite Database Optimization (Compression & Sub-5ms Query Acceleration)

**Date:** 2026-08-11  
**Status:** Approved  
**Target Output:** `english_dataset.db` & `core_3000.db` (Mobile Packaging Engine)  

---

## 1. Executive Summary & Goals

This specification outlines the technical design for optimizing the mobile SQLite database generated by `vocab-craft-engine`. The goal is to achieve a **35–45% reduction in database file size** while guaranteeing **query execution latency of < 5.0 ms** (targeting < 1.0 ms average) across all core mobile query paths using **standard, stock SQLite** available on iOS, Android, Flutter, and React Native platforms without requiring custom C extensions.

### Key Objectives:
1. **Size Reduction:** Reduce overall database size by 35–45% via Integer Enum encoding, `WITHOUT ROWID` link tables, External Content FTS5 indexing, and compact distractor arrays.
2. **Query Latency (< 5ms SLA):** Achieve sub-millisecond to sub-5ms latency across Lemma Lookup, FTS5 Prefix Search, Reflex Distractor Sampling, and Topic/Relation JOINs.
3. **Compatibility:** 100% stock SQLite native compatibility with convenient SQL Views for human-readable fallback.
4. **Automated Verification:** Pipeline benchmark integration verifying foreign keys, integrity, size reduction, and sub-5ms performance.

## 2. Architecture & Database Schema Optimization

### 2.1 Integer ENUM Mappings
Repetitive text strings across millions of rows are mapped to 1-byte `TINYINT` / `INTEGER` codes to drastically shrink storage and index sizes.

* **CEFR Levels (`cefr_level` TINYINT):**
  - `0`: Unknown, `1`: A1, `2`: A2, `3`: B1, `4`: B2, `5`: C1, `6`: C2
* **Part of Speech (`pos` TINYINT):**
  - `0`: other, `1`: noun, `2`: verb, `3`: adj, `4`: adv, `5`: pronoun, `6`: prep, `7`: conj, `8`: interj, `9`: phrase
* **Relation Types (`relation_type` TINYINT):**
  - `1`: synonym, `2`: antonym, `3`: hypernym, `4`: hyponym
* **Reflex Drill Types (`drill_type` TINYINT):**
  - `1`: speed_translation, `2`: cloze_reflex, `3`: listening_speed

### 2.2 Table Structures & `WITHOUT ROWID` Link Tables
Eliminate redundant `rowid` columns and auxiliary B-Trees on many-to-many junction tables:

```sql
-- Words Table with Integer Enums
CREATE TABLE IF NOT EXISTS words (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    lemma TEXT NOT NULL UNIQUE,
    pos TINYINT NOT NULL DEFAULT 0,
    ipa_uk TEXT,
    ipa_us TEXT,
    frequency_rank INTEGER,
    cefr_level TINYINT NOT NULL DEFAULT 0
);

-- WITHOUT ROWID Junction Tables
CREATE TABLE IF NOT EXISTS word_topics (
    word_id INTEGER NOT NULL,
    topic TEXT NOT NULL,
    PRIMARY KEY (word_id, topic),
    FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE
) WITHOUT ROWID;

CREATE TABLE IF NOT EXISTS word_relations (
    word_id INTEGER NOT NULL,
    relation_type TINYINT NOT NULL,
    target_word_id INTEGER,
    target_text TEXT NOT NULL,
    PRIMARY KEY (word_id, relation_type, target_text),
    FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE
) WITHOUT ROWID;

CREATE TABLE IF NOT EXISTS phrase_sentences (
    phrase_id INTEGER NOT NULL,
    sentence_id INTEGER NOT NULL,
    PRIMARY KEY (phrase_id, sentence_id),
    FOREIGN KEY (phrase_id) REFERENCES phrases(id) ON DELETE CASCADE,
    FOREIGN KEY (sentence_id) REFERENCES sentences(id) ON DELETE CASCADE
) WITHOUT ROWID;
```

### 2.3 FTS5 External Content Tables
Prevent text duplication between storage tables and full-text search indexes:

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS words_fts USING fts5(
    lemma,
    content='words',
    content_rowid='id',
    tokenize='porter ascii'
);
```

### 2.4 SQL Views for Client Backward Compatibility
Provide seamless SQL Views to map Integer Enums back to human-readable strings for mobile clients that prefer text queries:

```sql
CREATE VIEW IF NOT EXISTS v_words AS
SELECT 
    id,
    lemma,
    CASE pos 
        WHEN 1 THEN 'noun' WHEN 2 THEN 'verb' WHEN 3 THEN 'adj' WHEN 4 THEN 'adv'
        WHEN 5 THEN 'pronoun' WHEN 6 THEN 'prep' WHEN 7 THEN 'conj' WHEN 8 THEN 'interj'
        WHEN 9 THEN 'phrase' ELSE 'other' END AS pos,
    ipa_uk,
    ipa_us,
    frequency_rank,
    CASE cefr_level 
        WHEN 1 THEN 'A1' WHEN 2 THEN 'A2' WHEN 3 THEN 'B1'
        WHEN 4 THEN 'B2' WHEN 5 THEN 'C1' WHEN 6 THEN 'C2' ELSE 'Unknown' END AS cefr_level
FROM words;
```

## 3. Query Optimization & Indexing Strategy

### 3.1 Covering Indexes
Covering indexes satisfy queries entirely within the B-Tree index without accessing main table data pages:

* `idx_words_lemma_cov`: `ON words(lemma, id, pos, cefr_level, frequency_rank, ipa_uk, ipa_us)`
* `idx_reflex_cov`: `ON reflex_drills(drill_type, id, sentence_id, prompt_text)`
* `idx_definitions_word`: `ON definitions(word_id, id, definition_vi)`

### 3.2 Fast Random Sampling for Reflex Drills
Eliminate `ORDER BY RANDOM()` table scans in favor of indexed min/max primary key sampling:

```sql
SELECT r.id, r.prompt_text, r.correct_answer, r.distractors_json, s.cefr_level
FROM reflex_drills r
JOIN sentences s ON r.sentence_id = s.id
WHERE r.drill_type = :type 
  AND r.id >= (
    SELECT ABS(RANDOM()) % (MAX(id) - MIN(id) + 1) + MIN(id) 
    FROM reflex_drills WHERE drill_type = :type
  )
LIMIT 1;
```

## 4. Packaging Pipeline & Mobile Integration

### 4.1 Exporter Optimization Process (`SQLiteExporter`)
1. **Pragma Setup:** `PRAGMA foreign_keys = ON;`
2. **Schema & Data Migration:** Convert text attributes to Enum Integers, rebuild junction tables `WITHOUT ROWID`, populate `words_fts`.
3. **Index Construction:** Create covering and lookup indexes.
4. **Query Planner Statistics:** Run `ANALYZE;` to populate `sqlite_stat1`.
5. **Space Optimization:** Set `PRAGMA page_size = 4096;` and execute `VACUUM;`.
6. **Production PRAGMAs:** Set `PRAGMA journal_mode = WAL;` and `PRAGMA synchronous = NORMAL;`.
7. **Automated Performance & Compression Benchmark:** Execute `benchmark_all_queries()` across 100 iterations per query type.

### 4.2 Recommended Mobile Client PRAGMAs
Clients should execute the following upon opening `english_dataset.db` or `core_3000.db`:
```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA mmap_size = 268435456; -- 256MB zero-copy Kernel page mapping
PRAGMA cache_size = -8000;    -- 8MB RAM Cache
PRAGMA query_only = ON;       -- Enforce read-only memory optimizations
```

   - Topic/Relation JOIN: Target < 1.5 ms
4. **Automated Unit Tests:**
   - Pytest suite in `tests/test_sqlite_exporter.py` validating schema, views, benchmark results, and foreign key integrity.
